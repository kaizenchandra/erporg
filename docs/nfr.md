Observed checks: zero axe violations in the four tested Phase 1 desktop states, keyboard dialog/390px mobile checks, eight browser/API tests and seventeen Java tests. These do not establish full WCAG conformance or workload performance. OIDC/MFA/provider logout passed in a separate sandbox test. Security remains blocked by the open high development-dependency finding and unexecuted production security reviews.

NFR-04 partial evidence: a local synthetic logical restore completed in 4.919 seconds, with 18 approved changes and 92 audit records reconciled by full-row digests and integrity checks. This does not satisfy production RPO/RTO: no PITR/WAL, offsite backup, full application/IdP recovery or production workload measured. Evidence: `evidence/restore-check.json`.

Further NFR-04 evidence: the restored database was used by an isolated API instance; Flyway validated migrations and authenticated reads/authorisation/logout passed without changing restored business content. Local API readiness was 9.753 seconds and the smoke exercise 11.851 seconds. Full-service production RPO/RTO is still blocked/unmeasured. See `evidence/restore-application-check.json`.

NFR-05 reporting safeguard (Phase 2): validation currently accepts at most 10,000 tenant employees and 256 future reporting date boundaries; excess produces a visible conflict. A PostgreSQL fixture with 10,001 additional employees verifies fail-closed behaviour. This is implemented/tested workload protection, not a measured latency/capacity achievement. The proposed 100k growth workload remains blocked for this workflow until validation is redesigned and benchmarked.

Benefits catalogue capacity (Phase 2): implemented/tested visible guard at 1000 configured references before eligibility filtering/pagination; PostgreSQL fixture with 1001 plans verifies rejection rather than partial results. This is workload protection, not measured throughput or achievement of API latency targets.

Benefits selection increment: bounded selection pages (1–100), up to five dependants, 10-second transactions, uniqueness/row locks/deferred reconciliation and mobile/accessibility automation verified. No load/latency, complete WCAG, availability, production security or recovery target is newly claimed; 24-table local restore/API evidence is in checkpoint. Production financial/provider rules remain blocked pending authoritative configuration.

Private document increment: 16 KiB content and unchanged 32 KiB JSON request limit, 100-record employee guard, 2-second connection/3-second scanner read timeouts, 10-second database transaction boundary, bounded pages/audit and fail-closed quarantine verified locally. Uploads are excluded from routine API latency targets; no latency/capacity achievement claimed. Local 26-table restore plus three independently copied objects/readback is measured in checkpoint, not production RPO/RTO. Automated accessibility/mobile checks passed; full WCAG/manual assistive review pending. Scanner freshness, encryption, production private storage and hosted CI/scan evidence remain release gates.

Document retry increment: three manual attempts, exact version check, bounded external scan, immutable result and concurrent winner verified. Routine latency targets exclude vendor-bound upload/rescan operations; no routine or scanner throughput benchmark claimed. Full suite also passed against local built frontend. Local recovery measured at 27 tables/five private objects; production availability/RPO/RTO, complete accessibility, scanner freshness and security release gates remain unachieved.

Document version increment: bounded 100-file/100-version policy, same upload/scanner/transaction limits, sequential database constraints and concurrent winner verified in PostgreSQL. Every version remains separately scanned/authorised; no new performance, production recovery or full accessibility claim. Local browser/restore evidence is recorded in verification/checkpoint. The mobile disclosure target defect found during automation was corrected for both version and audit disclosures.

Template/completeness increment: 100 immutable templates, 4000-character text and bounded live per-template version lookups. Excess template configuration rejects visibly rather than returning a partial completeness result. This protects workloads but does not establish p95/p99 or 100k workforce capacity. Date boundary uses injected Clock; writes use 10-second transactions and root/employee locks. Automated mobile/form axe and restored API checks are scoped evidence only; full WCAG, assistive review, load and production recovery/security targets remain open.

Tenant/employee/root locks bound transaction scope at 10 seconds; throughput, lock contention and worst-case 100×100 projection latency remain unmeasured. Accessibility/browser/restore results are scoped in verification; no new production availability/recovery/security or full WCAG claim.

Retention/hold increment: at most 100 per-chain governance events, bounded private review/history and existing 10-second transaction scope.
