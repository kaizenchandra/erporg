# Phase 2 increment AY: approved declared-entity assignment

Prerequisites: immutable declared legal-entity catalogue and independently reviewed retirement, shared versioned employee approval/audit/inbox workflow and episode-owned employment selection. All 45 source IDs remain in scope. HR-01/HR-03/SH-01/SH-02/SH-03/SH-05/SH-06/SH-09 remain partial.

Reversible local policy: HR may propose an effective-dated **declared employing entity reference**, or explicit unassignment. Another HR subject AND employee must review; a target employee cannot approve their own record. Only HR and the target employee see the field/history; managers receive null and cannot propose/review. The reference declares supplied country/currency/time-zone metadata; it establishes no legal registration, contract change, statutory rules, bank/payment or payroll activation. No SAP/Workday integration.

Dates use UTC write eligibility (today through one year), local business-effective dates and separate UTC recorded instants. Assignment must fall within the selected employment episode and after reference creation effectiveness. References with a pending or approved retirement are unavailable for assignment; rejected retirement attempts do not block it. Approval revalidates reference/retirement and exact employee version. Immutable reference metadata acts as the retained source snapshot; no policy inference/backfill. Assignments never carry into a new rehire episode.

Conservative governance: any approved use permanently blocks NEW retirement proposals, even after unassignment. Existing command replay is checked first. A pending retirement and an assignment compete under the same tenant lock; module-owned SQL parent locks and source guards provide a second integrity boundary. General assigned-reference correction/retirement remains a later governed workflow, not an unsafe delete/edit.

Architecture: thin shared HTTP adapter → PeopleUseCases.submit/decide → pure EntityAssignment invariants → PeopleStore ports, composed with bounded READ_COMMITTED writes. A dedicated HR-only request-context use case exposes the immutable reference and current retirement blocker for informed review in repeatable-read context. Module-owned JDBC adapters alone access Core HR tables.
