# Phase 2 increment BJ: current department parent correction

Prerequisites: immutable department creation/audit, complete tenant reference directory and authenticated HR configuration. Scope HR-02, SH-01, SH-05 and SH-06. This is an HR reference-configuration action, matching existing direct HR creation governance; no independent approval stage is invented or claimed.

Acceptance before implementation:

1. HR can inspect a tenant department's declared/current parent, original start, exact current revision and complete paginated parent-correction history, including old/new parent, actor, reason, business-effective date, UTC recording instant and correlation. All other roles and other tenants are denied this configuration/audit context. Page0–100000, size1–50. Context uses one bounded read-only repeatable snapshot and UTC date.
2. HR may correct only a department already effective on the server UTC business date, to another currently effective tenant department or root. Require exact nonnegative signed-64-bit revision, bounded reason, stable command key and scope/impact confirmation in UI. The command pins the displayed UTC date and requires a context reload after date rollover; identical retries retain the original date. Each correction is effective on that UTC date; same-day corrections are ordered by revision. Original declarations and every correction remain immutable; earlier business dates resolve prior parent values. No future/backdated scheduling in this slice. Date-only history is not intraday/as-recorded reconstruction.
3. Domain rejects self/ancestor cycles, no-op, unavailable/planned target or parent and stale revisions. Resolve current actor inside the write transaction; serialize tenant hierarchy changes/department creation before reads. Identical replay returns original recorded result across later dates; changed payload/key reuse conflicts. Concurrent commands have one exact-version winner. PostgreSQL constraints/triggers independently guard parent existence/chronology, revision/order/old-parent snapshots, cycle prevention and immutable declarations/history. No partial mutation on failure.
4. Effective parent projection must feed all existing department-directory parent names, roots, exact-parent filters and direct-child reference counts, plus legacy department reads. Keep original creation history and replay snapshots unchanged. Parent corrections never change employee manager relationships, employment department, positions, cost-centre mappings or accounting. Display this impact before confirmation.
5. Real UI → API → PostgreSQL correction and root correction, focused error/preserved draft, history paging/refresh, unsaved handling, cancellation and keyboard/mobile accessibility checks. Domain, PostgreSQL integrity/concurrency/tenant/version/replay/date tests, API contracts, full Java/architecture and browser regressions. Upgrade retained synthetic schema without rewriting historical migrations; add the new journal to backup manifests and exercise actual restore/recovered effective projection before claiming recovery for the new table.

All45 source IDs remain in scope. Future hierarchy proposals/scheduling, independent approval/delegation policies, renames, costing and other Phase2/Phase3–7 behaviours remain planned. Do not mark HR-02 or Phase2 complete. Production remains NOT READY.
