# Design system
Atlas: original enterprise workspace informed by public SAP Employee Central descriptions (https://www.sap.com/uk/products/hcm/employee-central-hris.html); no claim of inspecting authenticated SAP/Workday screens.

White and cool gray surfaces, slate navy sidebar, teal primary action. Tokens in app/globals.css: 4/8/12/16/24/32 spacing, 8/12/16 radii, fine gray borders, quiet shadows. System sans typography, 14px body, 32px page title. Consistent inline SVG stroke icons. Status labels include text plus color. Hover, focus-visible, selected, disabled, busy, error and empty states explicit. Reduced-motion respected.

Persistent global navigation, workspace context, directory search, department/status filters, sortable name, page size/pagination, column control. Selection applies only to explicitly selected records; no consequential bulk action in Phase 1. Profile and request panels use native modal dialog, trapped focus and return focus. Native labels, inline errors, preserved drafts, unsaved-change confirmation, request progress and live status. Consequential approval shows field, old/new value, effective date and reason. Responsive directory switches to cards; sidebar collapses on mobile.

Gate: inspect shell, directory, profile and inbox at desktop/mobile; keyboard-only dialog and form review; automated accessibility supplemented with screen-reader review before AA claim. Synthetic data only. Loading, empty, errors, long content and denied states must be exercised. No WCAG conformance claim from automated tests alone.

Exit coordination: HR assigns operational tasks inside the approved resignation panel; the assignment form preserves values, links errors, warns on unsaved panel exit and prevents closure while submitting. My exit tasks is a separate own-assignment workspace for all roles with server filtering/pagination, overdue text, explicit completion impact and private audit disclosures. Completing a task is a manual attestation, never a claim of payroll/access execution. OPEN uses slate #526571 on #eef3f5; COMPLETED uses the existing green #267347 on #edf7f1, with text labels. Growing feature tabs scroll within their container. Mobile uses task cards rather than a dense table.

Task management adds an inline HR form in the approved-case panel, with explicit former/new access impact, required reason, version conflict recovery, preserved values, error links/focus and unsaved/busy guards. On success, the case heading receives focus and a status announcement accompanies refreshed authoritative data. HR-only management history is separate from ordinary task audit. CANCELLED has a text label and the existing slate treatment (#526571 on #edf1f4); current assignees see cancellation context without HR reasons. Adjacent task history disclosures have 44px minimum targets and padding, verified after an initial axe target-size finding. Mobile cancelled tasks remain cards with no completion action.

Employment-end withdrawal X reuses the existing contextual panel, labelled native form, status text, error summary/inline reason and mobile layout. Original schedule and each request/review remain visible to HR. Impact copy distinguishes pending cutoff, approved suppression and external actions. Own/alias review actions are hidden and backend-denied. Required reason errors preserve input and focus the summary; closing warns about unsaved values; repeat submission is disabled in flight and reuses its stable key. Completed mutations restore focus to the employment-end heading. Full manual assistive-technology/zoom coverage remains a release gate; automated axe checks cover the exercised mobile state only.

End-date replacement Y uses a separate labelled request/review section in the existing HR context panel. Current and original dates are distinguished; prior cutoff, request reason, independent reviewer and decision remain visible. Impact copy explains unchanged pending access, replacement midnight UTC, task/report checks and pending external steps. Only one child form may be edited at once; dirty/busy state combines across withdrawal and replacement forms so closing cannot discard another form's values. Escape from the new native date field moves focus to its reason without closing the dialog; subsequent Escape uses the unsaved-change guard. Validation keeps entered date/reason and focuses linked errors; confirmed outcomes restore the heading. Browser time only guides availability of controls; backend dates and authorisation remain authoritative. Further replacement/withdrawal is visibly unavailable after the first approval.

Rehire Z adds a private HR-only employment-episode section inside the existing employee profile. Original and returning start/end states are separate; the original recording time is explicitly unavailable rather than invented. Inline request collects new start/job/department/location/configured manager/reason; independent review shows scope, retained identity and blocked legacy access. Error summaries link to fields, retain values and focus the summary. New native date Escape moves to reason; profile close warns on unsaved values and change navigation is disabled while editing/saving. Busy/stable-key handling prevents concurrent submissions. Confirmed writes refresh authoritative context/profile; a failed follow-up profile read reports a recorded outcome and recovery rather than pretending the write failed. Mobile/keyboard/axe checks remain scoped evidence, not full WCAG/manual assistive conformance.

Rehire activation AA uses the profile's contextual completion panel. It explains manual HR attestation, nominated existing identity, Employee-only impact, other alias/session denial and pending external/payroll work before confirmation. Persistent labels, focused linked error summary, retained values, stable command key, concurrent-submit guard, unsaved-close handling and independent review are exercised in browser tests. Confirmed outcomes refresh profile and directory state. Session-upgrade recovery returns users to the correct sign-in screen. Automated mobile axe is bounded evidence; manual screen-reader/zoom checks and complete WCAG conformance remain open.

AB adds a Current local access section below the historical onboarding/grant receipt. It distinguishes GRANTED from REVOKED, shows nominated identity/Employee-only scope, confirms immediate impact before submission and requires a persistent reason label. Blank input focuses a linked error summary; values survive errors and unsaved-close dismissal. Concurrent submissions are blocked. Confirmed revocation displays the private actor/time/reason receipt, preserves Active employment and explains pending provider/payroll and unavailable replacement. Refresh after uncertain outcome can confirm a committed revocation without another command. Desktop table and mobile card labels are tested separately; mobile axe/overflow and visual evidence remain bounded checks, not full WCAG conformance.

## Increment AC identity replacement
Use existing neutral/navy/teal primitives and contextual employee panel. HR sees current access, one replacement history and request/review forms; the requester sees no review action. Consequential approval states the old/new identity and fresh Employee-only scope. Preserve entered reason after validation, stable command key, exact snapshot, inline error focus, unsaved-close guard and confirmed outcome; frozen review target prevents refreshing into another request. A busy profile close button is visibly disabled while parent refresh completes. Disclosure exposes both private grant and revocation histories after replacement. Mobile layout uses cards, persistent labels, status text and no table shrink. Automated axe/overflow and visual checks are evidence scoped to tested states, not complete WCAG conformance.

## Increment AD: pending resignation withdrawal
Use existing private resignation dialog, labels, status badges, neutral/navy/teal tokens and mobile cards. Only the original requester sees withdrawal for a pending request. Show date/impact, required reason, inline error/focus, stable key, unsaved close and disabled busy close; wait for server confirmation. Withdrawn status/filter/history retain original reason and show a separate receipt actor/time/correlation. Reopening recovers uncertain outcomes without silent retries. Approved resignation withdrawal remains unavailable.

## Increment AE: case episode provenance
The private case dialog identifies its owning original employment episode and start-date snapshot. Distinguish submission recording time from the later capture of a legacy link. Keep detailed actor/correlation provenance in a disclosure. Reads have a status announcement, focused error/retry, cancellation on close and no shared sensitive cache. Use existing neutral/navy/teal primitives, labelled definition rows and mobile cards; no new visual tokens. A first rehire changes current employment, not the prior case's displayed ownership. No controls imply that a new-episode resignation is enabled.

Increment AF keeps the existing shell/profile/case design and tokens. The current profile's effective status remains distinct from the immutable original case ownership; one retained-data mobile browser regression and screenshot inspection passed after the backend projection upgrade. No new frontend controls or later-cycle actions were introduced.

Increment AH uses the existing assignment, management and employee task screens. Validation retains entered values; assignee access failures use the established inline/error-summary pattern. The targeted browser workflow verified HR assignment/reassignment and Employee mobile completion with semantic COMPLETED status, private management reasons hidden, axe checks and no horizontal overflow. The mobile screenshot was inspected. No new design token, frontend business policy or additional lifecycle action was introduced.

Increment AI adds Recorded legal name to the existing employee profile and private change selector. Unrecorded values say “Not recorded”; unauthorised team reads say “Restricted”. The form explains supplied-value recording and separate document verification only when this field is selected; it offers no ordinary remove-value action. Review headers now consistently use shared human-readable field labels. Existing persistent labels, preserved values, error-summary focus, independent approval and effective history are reused. Targeted real mobile profile/axe/overflow checks passed; no new token or interaction pattern is introduced.

### AJ: additional contacts in the private employee profile

The existing neutral surfaces, navy navigation, blue actions and semantic status badges continue. A private profile section distinguishes the primary contact above from up to four additional contacts. It provides current contact details, effective date, status filter and eight-request history pages. No bulk operation applies. Request details disclose OLD/NEW snapshots and decision provenance; authorised independent HR reviews from this context. This is a profile workflow, not a claim that these requests are unified into the shared approval inbox or delegation capability.

The editor describes the replacement scope before submission, offers labelled contact rows, removal and required date/reason, and preserves values on failure. Backend field validation links inline errors to fields and focuses the summary. A stable key per unchanged payload recovers an uncertain response without duplicate requests. Dirty forms warn on close/navigation; pending mutations disable close/submission. Reads abort on unmount/context change, time out and offer retry. Nested native dialogs use unique accessible title IDs, contain keyboard focus and stop Escape propagation to the outer profile. The mobile profile uses stacked content, not a compressed data table. Browser axe checks and visual inspection are recorded separately from broader WCAG manual conformance.

### AK: contacts in Approvals

Approvals offers Employee changes and Emergency contacts categories. The existing navigation badge is labelled in context as an employee-change count; contact counts apply to the selected queue scope and status. The HR review scope excludes non-independent requests; My employee record tracks private own requests for all roles. Status filters and eight-item pages preserve bounded navigation. Cards show employee ID, effective date, reason and expandable OLD/NEW and decision provenance. The shared AJ review dialog avoids duplicating form behaviour. On success or uncertain close, revalidate the queue and restore focus to its heading after data returns. Reads abort on category navigation and identity change, time out and provide a focused retry error. Existing tokens, 44px selects, status text and mobile stacked cards apply. No bulk decision or delegation is supplied.
