# Design system
Atlas: original enterprise workspace informed by public SAP Employee Central descriptions (https://www.sap.com/uk/products/hcm/employee-central-hris.html); no claim of inspecting authenticated SAP/Workday screens.

White and cool gray surfaces, slate navy sidebar, teal primary action. Tokens in app/globals.css: 4/8/12/16/24/32 spacing, 8/12/16 radii, fine gray borders, quiet shadows. System sans typography, 14px body, 32px page title. Consistent inline SVG stroke icons. Status labels include text plus color. Hover, focus-visible, selected, disabled, busy, error and empty states explicit. Reduced-motion respected.

Persistent global navigation, workspace context, directory search, department/status filters, sortable name, page size/pagination, column control. Selection applies only to explicitly selected records; no consequential bulk action in Phase 1. Profile and request panels use native modal dialog, trapped focus and return focus. Native labels, inline errors, preserved drafts, unsaved-change confirmation, request progress and live status. Consequential approval shows field, old/new value, effective date and reason. Responsive directory switches to cards; sidebar collapses on mobile.

Gate: inspect shell, directory, profile and inbox at desktop/mobile; keyboard-only dialog and form review; automated accessibility supplemented with screen-reader review before AA claim. Synthetic data only. Loading, empty, errors, long content and denied states must be exercised. No WCAG conformance claim from automated tests alone.

Exit coordination: HR assigns operational tasks inside the approved resignation panel; the assignment form preserves values, links errors, warns on unsaved panel exit and prevents closure while submitting. My exit tasks is a separate own-assignment workspace for all roles with server filtering/pagination, overdue text, explicit completion impact and private audit disclosures. Completing a task is a manual attestation, never a claim of payroll/access execution. OPEN uses slate #526571 on #eef3f5; COMPLETED uses the existing green #267347 on #edf7f1, with text labels. Growing feature tabs scroll within their container. Mobile uses task cards rather than a dense table.

Task management adds an inline HR form in the approved-case panel, with explicit former/new access impact, required reason, version conflict recovery, preserved values, error links/focus and unsaved/busy guards. On success, the case heading receives focus and a status announcement accompanies refreshed authoritative data. HR-only management history is separate from ordinary task audit. CANCELLED has a text label and the existing slate treatment (#526571 on #edf1f4); current assignees see cancellation context without HR reasons. Adjacent task history disclosures have 44px minimum targets and padding, verified after an initial axe target-size finding. Mobile cancelled tasks remain cards with no completion action.

Employment-end withdrawal X reuses the existing contextual panel, labelled native form, status text, error summary/inline reason and mobile layout. Original schedule and each request/review remain visible to HR. Impact copy distinguishes pending cutoff, approved suppression and external actions. Own/alias review actions are hidden and backend-denied. Required reason errors preserve input and focus the summary; closing warns about unsaved values; repeat submission is disabled in flight and reuses its stable key. Completed mutations restore focus to the employment-end heading. Full manual assistive-technology/zoom coverage remains a release gate; automated axe checks cover the exercised mobile state only.

End-date replacement Y uses a separate labelled request/review section in the existing HR context panel. Current and original dates are distinguished; prior cutoff, request reason, independent reviewer and decision remain visible. Impact copy explains unchanged pending access, replacement midnight UTC, task/report checks and pending external steps. Only one child form may be edited at once; dirty/busy state combines across withdrawal and replacement forms so closing cannot discard another form's values. Escape from the new native date field moves focus to its reason without closing the dialog; subsequent Escape uses the unsaved-change guard. Validation keeps entered date/reason and focuses linked errors; confirmed outcomes restore the heading. Browser time only guides availability of controls; backend dates and authorisation remain authoritative. Further replacement/withdrawal is visibly unavailable after the first approval.

Rehire Z adds a private HR-only employment-episode section inside the existing employee profile. Original and returning start/end states are separate; the original recording time is explicitly unavailable rather than invented. Inline request collects new start/job/department/location/configured manager/reason; independent review shows scope, retained identity and blocked legacy access. Error summaries link to fields, retain values and focus the summary. New native date Escape moves to reason; profile close warns on unsaved values and change navigation is disabled while editing/saving. Busy/stable-key handling prevents concurrent submissions. Confirmed writes refresh authoritative context/profile; a failed follow-up profile read reports a recorded outcome and recovery rather than pretending the write failed. Mobile/keyboard/axe checks remain scoped evidence, not full WCAG/manual assistive conformance.

Rehire activation AA uses the profile's contextual completion panel. It explains manual HR attestation, nominated existing identity, Employee-only impact, other alias/session denial and pending external/payroll work before confirmation. Persistent labels, focused linked error summary, retained values, stable command key, concurrent-submit guard, unsaved-close handling and independent review are exercised in browser tests. Confirmed outcomes refresh profile and directory state. Session-upgrade recovery returns users to the correct sign-in screen. Automated mobile axe is bounded evidence; manual screen-reader/zoom checks and complete WCAG conformance remain open.
