# Threat model and privacy
Baseline: OWASP ASVS 5.0 Level 2 proposed scope (https://owasp.org/www-project-application-security-verification-standard/), no certification claim.

| Threat | Control | Release evidence required |
|---|---|---|
| Employee enumeration / tenant spoofing | Server-owned identity membership; every query tenant-scoped and record policy | Cross-tenant and direct-object negative tests |
| Forged or replayed approvals | CSRF, independent approver, version lock, idempotency | Concurrent approval and duplicate tests |
| Privilege escalation | Deny by default, allowlisted fields, no client role trust | Employee/manager/HR API matrix |
| Session theft | HttpOnly, same-site cookies, TLS, session expiry/logout | OIDC/MFA/revocation integration test |
| Injection and XSS | Prepared SQL, React output encoding, bounded values | Validation and static scan |
| Private data in logs | No request payload logging; safe errors and correlation IDs | Log inspection |
| Document malware / disclosure | Phase 2 private storage, size/type validation, quarantine scan and authorised download | Malware and access tests before DS-01 exit |
| Exports / admin abuse | Scoped asynchronous bounded exports, audit, segregation of duties | Phase 7 export/privacy verification |

No real employee data in local builds. Personal/contact records: configured retention after employment; employment and payroll history: statutory retention pending jurisdiction; financial records: archival and correction, never generic deletion; documents: category-specific retention; legal hold overrides deletion. SH-10 will implement authorised access requests, policy decisions and anonymisation with immutable decision audit. Retention durations require accountable legal owner; no invented statutory periods.

Production prerequisites: managed TLS, encrypted database/backups/object storage, external secrets, OIDC audience/issuer validation, privileged MFA, revocation integration, rate limiting at ingress, bounded request bodies, deployment-specific CORS (same origin by default), tested CSP, security/dependency/container/secret scans. Local authentication is not evidence of OIDC readiness.

JDBC session hardening: PostgreSQL now persists sessions with a 30-minute idle timeout and HttpOnly cookie, with Secure enabled in production configuration. Tested logout revokes a copied cookie across two API instances; expiry and application restart behavior were exercised. Persisted attributes can contain authentication/CSRF/OIDC state: restrict DB access, encrypt storage, never log attribute bytes or export them as business data. Logical restore drills exclude session and attribute data and assert both tables are empty after restore. Full production/PITR restores must invalidate sessions before opening traffic to avoid restoring previously revoked credentials. Backchannel IdP revocation, administrator revoke-all and production multi-node failover remain unverified.

Private contact policy (Phase 2 increment): self/HR may read home-address/emergency-contact fields; team managers receive null values. Managers cannot submit or decide private team changes. Request lists and pending totals exclude private team requests and audit reads exclude their entries; private free-text reasons therefore remain within the same restricted workflow. This is enforced by application policy, not hidden controls. Direct API and PostgreSQL tests cover profile, directory, legacy employee/request list, inbox/count, history and decision paths. Multiple contacts, full privacy administration and retention ownership remain open.

Hiring access: all hiring lists, submissions, decisions and audits are backend HR-only and tenant-scoped. Independent review checks employee identity in addition to provider subject, preventing alternate-login self approval. Pending request snapshots and audits contain HR-controlled employee inputs and must use their own retention/hold rules. No employee receives a credential or membership automatically. Olivia is a local synthetic reviewer; production IdP role provisioning/MFA remains a release dependency. Acceptance-only rate budgets are bounded and guarded against prod; default rate/body/forwarded-IP behavior is tested deterministically.

Manual onboarding confirmation is HR-only and requires approved tenant-scoped hire, matching employee version and nonempty reason. Backend locks and database constraints prevent duplicate/concurrent state changes. History is authorised per employee; reasons are visible to HR/self and redacted for team managers. Immutable history retains actor, business date, recorded instant and correlation. Pending events have no delivery consumer yet. Existing CSRF/session/request guards apply; no release security claim is added.

Optional-field removal retains historical private values in immutable authorised audit; it is not an erasure request. HR review and existing field-level redaction apply to both removal requests and audit. Blank input without the explicit UI checkbox is rejected. Retention/legal-hold/privacy administration remains open under SH-10.

Position references are intentionally organisation-wide metadata within the authenticated tenant. Only HR can create or read reason/actor configuration history; employee/manager reads contain code/title/department/date only. Tenant context comes from server identity. Validation errors never echo submitted values. CSRF, request-size, rate and session controls apply. Configuration audit retains reason/correlation and immutable business snapshots.

Position assignment follows reporting-line access: only HR or the authorised team manager can initiate; employees can view their own assignment but cannot alter it. Decisions also deny a reviewer whose employee ID matches the requester’s server-resolved membership, even under an alternate subject. Requester membership rebinding is not a supported workflow; immutable historical requester binding/governance remains a release prerequisite before enabling identity reassignment. Unknown tenant positions and mismatched departments fail without mutation. Position metadata is not a private contact field, so authorised team managers can inspect assignment audit.

Reporting changes can be initiated by HR or current team manager but decided only by independent HR, with existing same-person/record/version controls. Manager candidate reads return only tenant-scoped identifier/name/start date to HR/managers. New manager must already have HR/MANAGER membership; no automatic privileged role grant. Effective-date team access is enforced server-side on profiles/history/list/count/inbox paths, not a UI check. Previously delivered client data cannot be recalled; new requests enforce current scope and refreshed navigation reloads it. Future/mutually concurrent cycles are rejected. Root removal, delegation and membership rebinding remain unsupported.

Display-name edits are employee-owned or HR-initiated, with HR-only decisions and existing same-person/tenant/version checks. Team managers can view authorised display names but cannot change them or approve a name request. Control characters are rejected; UI renders values as encoded text. Privileged roles, subject, employee ID and email do not change with a display name. Historical name values remain in authorised audit; privacy erasure/retention administration remains open.

Withdrawal is permitted only to the original authenticated requester subject, with current private-field visibility where required. HR/team-manager privilege does not confer ownership. Approval versus withdrawal is serialized on request row; each terminal state preserves its permitted actor relationship in database constraints. Explicit command version is mandatory. Replay after date boundaries returns only owner-authorised existing context and cannot be used to submit a new backdated change. No approval reversal or delegated cancellation exists.

Benefits configuration/history is HR-only; catalogue eligibility always uses authenticated self context through the published Core HR contract. No client employee/tenant ID selects a different workforce record. Plan definitions are tenant-scoped; only own eligibility explanations are returned. Manager access to team private benefit selections is not introduced. Contribution/rule references are demonstration configuration, not statutory deductions. Bounded strings/decimal/service values and private-cache/no-store/request guards apply; reason audit is immutable.

Benefits selections: self-only submission; HR tenant review; managers and other employees receive only their own selection records, including dependant fields. No arbitrary employee/tenant input accepted for submission. Review requires HR and a different employee ID, not merely a different login. Published HR employment lookup denies managers requesting another employee. All decision and submission paths use server session context, CSRF and existing limits. Dependant names/relationships and selection reasons are private; no values added to telemetry/errors. Pending payroll handoff contains no bank details.

Retention decision remains unresolved for benefits history/dependants: synthetic development records only; no generic delete endpoint or production retention claim. Country/company enrolment policy, legal holds, lawful retention/deletion/anonymisation and provider handling must be approved before real data/release. Cancellations and privileged delegation are unavailable and remain tracked gaps.

Documents threat controls: private employee files, filenames and reasons are sensitive. Identity/tenant/employee come from the server's published membership contract. Managers receive no team document access. Direct content/history calls repeat record/tenant checks; opaque UUIDs and hidden controls grant no permission. Input is .txt/text/plain, strict UTF-8 without binary controls, 16 KiB maximum within the unchanged 32 KiB JSON request limit. File names cannot contain paths/control characters/consecutive dots. Storage keys never derive from a filename. No inline rendering; attachment/no-store/nosniff/sandbox response and output encoding. Scan error/unavailability quarantines; EICAR detection rejects. Corrupt stored content is denied, not served. Logs/errors contain no bytes, names, storage paths or document keys.

Local ClamAV TCP is bound only to loopback; the protocol is unauthenticated and requires an isolated/authenticated service boundary before production. Local bundled signatures have no freshness SLA; updating/freshness alerts and scanner deployment hardening are release gates. POSIX file permissions are not encryption at rest. Local storage and this composition root are unavailable in prod. Retention, legal hold, archival, deletion/anonymisation, country/company document policies, versions/templates/completeness and production private object storage remain unresolved; synthetic data only. Unreferenced/quarantined/rejected objects are retained privately, with no generic deletion endpoint. Requests/downloads abort when UI context unmounts; session expiry clears sensitive workspace state.

Document scan retry controls: HR-only backend permission, tenant-filtered lookup before object retrieval, exact expected attempt/version, reason and stable command key. Before scanning, hash/size/type validation repeats against immutable upload metadata. Before commit, current authoritative identity must still match the original HR/tenant/employee context; revoked privileges or rebinding deny the commit. Quarantine retries are capped at three; malware/clean states cannot be retried to bypass a final decision. A stale or competing commit returns conflict. Every result is immutable and includes the server actor/correlation; no bytes/key/hash are returned by public DTOs. Employee/manager/other-tenant direct requests denied. Scanner failure stays quarantined; corruption is denied before any vendor scan. UI downloads now wire unmount cancellation into the network request as well as suppressing stale completion.

Document versions: self or tenant HR can replace only the current version. Manager team access and other-tenant identifiers are denied. Each version is independently scanned; rejected/quarantined latest files cannot cause silent fallback. Historical retrieval repeats record permissions and clean/hash/size validation. Global command keys bind owner/root/parent/ordinal/file/reason; stale branches and conflicting replay fail. V24 owner/snapshot/sequential checks and immutable ledger prevent normal SQL workflow mutation; privileged database-owner tampering remains an operations/control concern. No version deletion/retention policy is inferred.

Template configuration is tenant-visible guidance, including creator/reason audit; HR must keep template text free of private employee values. Only HR creates configuration. Classification/history/completeness are self/tenant-HR only, including direct API calls; managers have no team access. A linked clean chain is not content approval or legal compliance. Only the current version can be classified, with exact ordinal and immutable audit; later blocked replacements remain blocked in completeness. Parameterised SQL and encoded plain text prevent injection/active template content. No template execution, merge expressions, public file URL or automated legal retention is introduced. Production document adapters remain disabled pending storage/encryption/scanner gates.

Template maintenance: HR-only append revision/retirement and classification correction; ordinary employees/managers/other-tenant identities cannot mutate. Authenticated tenant members may read configuration revision history, including future text; employee classification history stays self/tenant-HR only. Exact ordinals, bound keys, current server identity and record ownership are checked before writes; current clean latest file required for correction. Previous chains remain reserved, preventing reuse to manufacture fresh evidence. Retirement removes the configured completeness obligation on its stated date without deleting records. Privileged HR may currently correct their own classification; independent approval, scoped configuration administration and reactivation/retirement withdrawal remain explicit gaps. No retention/deletion policy is inferred.

Retention/hold threat controls: legal case references, policy basis and governance audit are private to HR; employees/managers/other tenants cannot retrieve or mutate them, even for an otherwise readable own document. Case data does not enter the employee-visible file audit. Exact expected journal ordinal prevents lost commands; keys bind root/action/input, with stable recorded replay after later events. Server identity is revalidated within transaction; release denies both original subject and original employee ID, including alias and subject rebinding. SQL repeats these independence/sequence/preservation rules. Reads do not fetch file bytes. No deletion authority or statutory policy is inferred; independent legal authority, finer case/privileged administration scopes and non-document record categories remain production design/verification gaps.

Organisation chart: server actor/tenant resolves inside the read snapshot; request parent/search/header identifiers never select tenant or role. Only scoped organisational fields are queried/mapped for nodes. HR tenant scope, manager self/current direct reports and employee self scope apply to roots/search/branches/counts and visible-manager context. Hidden managers are represented by a boundary flag, not an identifier; hidden grandchildren do not contribute counts. The chart's profile action calls the separately authorised profile API; cancellation prevents a delayed old-context response from opening after navigation or identity change. No export, whole-tenant client graph or contact/private-field DTO is introduced.

Resignation threat/control increment: reasons, proposed dates and HR comments are private self/HR case data; managers have own-case access only, independent of directory/team scope. Backend resolves current membership/tenant within the transaction and ignores supplied role/tenant headers. Self-review checks subject and target employee to deny identity aliases. Parameterised scoped reads, exact versions, serialised employee/request locks, immutable snapshots/audit and deferred handoff reconciliation protect disclosure, replay and concurrent-review risks. Outcome notifications omit reason/comment. Approval does not revoke sessions or claim termination; dated revocation and final exit controls remain required future work. Existing ASVS scope/findings and production release blockers are unchanged.

Exit-task increment U: operational instructions/reasons are sensitive task data. HR can inspect tenant case tasks; ordinary roles can inspect only tasks assigned to their current employee identity. Assignment does not expose resignation reasons, review comments or whole-case tasks. Independent HR coordination excludes the departing employee; completion is assignee-only, including when a different HR user attempts proxy completion. Tenant and actor resolve on the server within use cases, including role/identity changes. Explicit versions, stable keys, case/task locks, immutable snapshots/audit and deferred SQL integrity address replay, concurrent command and history-tampering risks. Notifications contain no instructions/reasons. UI instructs coordinators not to include credentials or private resignation details. No account revocation, financial settlement or privacy deletion is inferred from task attestation; those controls remain open.

Exit-task management V: current assignment is an authorisation fact, not an editable UI label. Former ordinary-role assignees lose subsequent list/history/completion access after reassignment. Assigned users never receive the HR-only reassignment/cancellation reasons, old/new identities or coordinator journal. HR sees tenant management history; the departing HR employee cannot coordinate their own case. Server membership/tenant checks, exact aggregate versions, base-task locking followed by fresh projection, immutable management events and SQL assignment/cancellation guards address replay, concurrency and obsolete-client risks. Already viewed local data cannot be recalled. Generic old/new assignment notifications omit sensitive reasons. No employment, payroll or identity-system action is executed. An older application that ignores current assignments is not a safe rollback build; production remains gated.

Employment end W: sign-in and every authenticated request validate effective local membership through the published Core HR contract. At the first inactive UTC date, all mapped subjects/aliases fail, new sign-in fails, and existing JDBC sessions are deleted on their next request. Membership rows/history are retained. Denial clears security context and expires the session cookie; it sets 401 directly to avoid POST error redispatch replacing the denial with a CSRF 403. Real HTTP tests verify three previously authenticated sessions (including an alias) at one nanosecond before and exactly at the cutoff, plus fresh sign-in denial and authorised HR reads. No remote provider account/session revocation or eager unused-session cleanup is claimed. Local policy still denies an ended employee even if the provider authenticates them.

Only independent HR can confirm/read detailed end context. Exact employee versions, replay keys, tenant workforce lock, immutable record and reconciled pending handoffs protect duplicates/concurrent scheduling and audit loss. Unfinished own/assigned exit tasks and current/planned report ownership block scheduling. New assignments/manager selection are rejected once an end is recorded. Role changes and dates remain server-controlled; no client-supplied date/tenant or runtime time-travel endpoint grants access. Older end-unaware API versions cannot safely serve a deployment after scheduling. Privacy/retention/rehire and employment-policy approval remain separately required production work.

Withdrawal X: only tenant HR can read the private submission/decision history or request/review it. Server-resolved subject AND employee enforce separation, including aliases and the departing HR employee. Pending/rejected requests cannot delay revocation. Approval at/after cutoff fails closed and cannot reactivate a former employee. All access paths use the current schedule projection, with immutable original records retained. Real HTTP tests verify both retained sessions/new sign-in after pre-effective approval and continued denial for a pending request at cutoff. Notifications omit reasons/comments. Direct browser role/tenant headers do not grant access. No live provider cancellation, external payment reversal or production identity assurance claim; existing ASVS scope and unresolved findings remain open.

End-date replacement Y: date changes can delay or accelerate local access denial, so request/review is HR-only and independent by subject and employee; departing employee and alias review are denied server-side. A pending/rejected request cannot change access. Approval after an effective current cutoff is forbidden; the current snapshot, date, open tasks and report handover are revalidated under the workforce lock. Existing/alias/new sessions follow the replacement date through the same active-membership contract. Original/withdrawn histories remain private; notifications omit reasons/comments. Current handoffs use approved command identity, not coincident timestamps/correlation IDs. No provider cancellation/rehire/payment or production ASVS claim is made; previous findings and release gates remain open.

Rehire Z threat: retained sessions/privileged mappings can survive an ended interval and must not become valid when employment resumes. Approved rehire therefore installs an additional local hold on every mapped identity, independent of date-based Onboarding status. No role/provider change occurs. Exact-clock HTTP tests retain two unused HR sessions/aliases across end and rehire, then verify 401 on use and fresh sign-in while HR still reads the new episode. Fresh access provisioning/session-episode binding is pending; no external account enablement or MFA assurance is inferred.

Only tenant HR reads/submits/reviews private rehire/episode context, with subject AND employee separation, no self/alias approval and server-resolved tenant. Every command rechecks snapshot/date/configuration/pending work under the workforce lock; immutable SQL records and deferred episode/handoff reconciliation protect audit loss/duplicates. Manager scope follows the new effective manager; tests verify the old manager loses directory scope. Pending old changes may be rejected by independent HR using a retained identity mapping for separation checks, without authenticating the ended requester; approval against Ended employment is forbidden. No deleted/missing identity is silently trusted. Legacy access is not restored by rejecting a request or by creating an episode.

Older APIs that only check Ended status would incorrectly accept old privileged mappings once Onboarding is projected. They are unsafe mixed-version/rollback targets after approval. Drain old readers before enabling writes; production rollout remains unverified. Existing ASVS scope, findings and release gates remain open. This is not certification or a completed identity lifecycle.

Rehire activation AA: independently reviewed manual completion nominates one existing tenant/employee identity and grants Employee-only local access. Legacy HR roles remain retained for history but never determine this fresh grant; other aliases stay denied. Identity mappings and references are checked again under the workforce lock before approval. Real PostgreSQL/HTTP tests retain an untouched pre-end session until after the grant and prove it cannot revive. Forged epoch/role headers do not supply the server-only authentication stamp. Missing stamps fail closed and require fresh sign-in; no compatibility bypass exists. OIDC callback stamps only after active local membership checks, without claiming IdP account enablement or provisioning.

Private completion/access history is HR-only, with subject AND employee separation and explicit target exclusion. Generic notifications omit reasons/comments; epochs are absent from output/log contracts. Append-only records and deferred reconciliation tie the completion and grant to one approved decision. One local grant only: administrative revocation/replacement, repeated employment cycles and live provider administration are unresolved release gates. Existing ASVS scope and prior findings remain open; this is not certification.

Fresh-grant revocation AB: immediate HR security suspension requires a non-target authorised employee, named grant, reason, exact snapshot and idempotency key. No second approval delays denial; this is a provisional company decision requiring an accountable policy owner before release. Tenant/role/record scope is server-derived; forged headers and target aliases do not grant authority. One immutable terminal event preserves original grant and privileged legacy mappings without allowing fallback. Every authenticated request and authentication callback uses the revoked-grant filter, so held sessions/new sign-ins fail even while employment stays Active. Real concurrent HTTP calls have one committed winner and one conflict. Private reasons remain in HR context/journal, not generic notifications.

This does not perform employment termination, external IdP disablement/session revocation, payroll actions or original-employment general suspension. No undo/replacement is implemented. Drain revocation-unaware binaries before enabling commands; older readers are unsafe rollback targets. Existing ASVS scope, dependency findings and operational gates remain open; no certification claim. Persistent local data and independent restored copies are now ignored, private canonical directories, never public assets or committed evidence contents. No earlier missing document bytes were recovered.

Persistent development private roots and restored copies are excluded from Git and both frontend/backend Docker build contexts. Backend images copy only pom/src and the packaged jar. Container builds/scans remain unexecuted; no production artefact or encryption/backup assurance is inferred.

## Increment AC threat controls
Identity replacement is privileged impersonation risk: existing mapped candidate only, no new IdP account; different unheld/unused subject, target employee excluded from request/review, two independent HR subject AND employee identities, exact current snapshot, bounded attempts, private reasons and auditable UTC/correlation receipts. Revalidate candidate and predecessor at approval. SQL constraints/locks protect atomic decision/grant reconciliation; auth rejects held and bound-but-remapped identities without raw-role fallback. New epoch invalidates unused earlier sessions; one replacement cannot restore historical HR privilege. Revoke replacement through the existing HR security action. Both original/replacement receipts remain HR-only and recoverable. Generic notifications contain no private reasons.

External IdP provisioning/revocation, privileged operational access and production security review remain open. Local successful tests are not OWASP ASVS certification. No new dependency audit executed this increment; prior five high development-tool findings remain unresolved.

## Increment AD: unreviewed resignation withdrawal
Prevent forged cancellation: validate authoritative tenant/employee/subject, require original requester (no same-employee alias or inferred delegation), exact request version, required reason and stable key. Lock employee then request for both HR review and withdrawal; one terminal transition wins. SQL guards and deferred reconciliation reject incomplete/forged state/receipt/audit. Receipt and reasons are self/HR-only; HR notification contains no private reason. Current identity checks retain episode/grant/held-subject restrictions. Withdrawal never re-enables a terminated account or undoes an approved end/handoff. No ASVS certification or new dependency audit claim.

Match each new link to the immutable request, source audit, actor/start/time/correlation; prevent replacement/deletion. A migration-only origin cannot be submitted afterward. V44 derives compatibility provenance only from a complete older original-case contract; unsupported new-episode data and incomplete sources fail. No privileged delegation or new actor roles are introduced. Source versus capture time remains explicit, avoiding invented audit history. Production binary/migration rehearsal and other ASVS/security gates remain open.

Legacy role suppression, global revoked-subject hold, fresh-epoch login and record/field controls are unchanged and covered by the full HTTP/backend regression. Increment AG binds local workforce epochs to immutable employment-episode provenance. Privileged access, OIDC/MFA production policy and external provider deprovisioning remain existing release gates; the full OIDC browser test was not rerun for AG.

Increment AH: task create/reassignment must find a currently workforce-authorised identity for the assignee. Increment AI: recorded legal name is private employee information, independent of public/display identity. ### AJ: private contact threat surface

Additional emergency contacts are personal data. New endpoints require server-resolved identity and tenant membership; self/HR scope is checked before command-shape validation, and record locks/version checks protect concurrent state changes. Manager/team visibility does not imply access. Independent reviewer policy rejects aliases mapped to the requester's employee. Parameterised JDBC reads/writes remain tenant scoped. Immutable snapshot/audit rows and deferred reconciliation prevent silent history loss; application-level authorisation remains required even with SQL integrity checks. Notifications expose only status. Read payloads use no shared cache, browser storage or telemetry; history is private and bounded. Retention/legal holds, production encryption/key management and external IdP operation still require release evidence. Existing AI legal-name reader quiescence/rollback restrictions continue to apply.

### AK: cross-record queue privacy

A private queue broadens HR discovery, so REVIEW requires HR at the application boundary and excludes both requester identity and employee aliases plus the target employee. OWN always resolves the authenticated employee; employee/tenant query parameters and forged headers cannot widen it. Tenant and scope predicates constrain both count and item queries. Non-HR REVIEW calls return denial rather than counts; no names, contacts or reasons appear in routine logs. The queue uses no shared cache. Decision endpoints continue to enforce independent review, exact versions and terminal/replay policy regardless of which UI opens them. Shared delegation, privileged operations and comprehensive ASVS/release findings remain as previously tracked.
